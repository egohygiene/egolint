# EgoLint identity brief

## Essence

EgoLint is the inspectable quality control plane for a repository. It brings many specialized tools
behind one calm interface, applies only the capabilities that fit the repository, and preserves
evidence instead of hiding complexity.

## Visual direction

Express an exact inspection system moving across multiple source layers. The mark combines three
code-like rails with a circular inspection gate and a verified check: teal represents reproducible
evidence, lime represents a clean signal, and violet connects EgoLint to the wider Ego Hygiene tool
family. Use deep ink surfaces, crisp rounded geometry, generous space, and high-contrast type. The
result should feel precise and energetic rather than punitive.

## Voice

Name the rule, affected location, evidence, and safest next action. Separate a policy finding from
an unavailable tool or execution failure. Prefer direct, technical language that respects the
maintainer's judgment and never treats an automated score as the whole truth.

## Avoid

- police, punishment, shame, surveillance, or grading imagery;
- dirty-versus-pure moral language or claims that software is universally safe;
- noisy walls of tool output without normalized evidence and remediation;
- green status claims when a capability was skipped, unavailable, or stale;
- suggesting that EgoLint replaces the underlying tools or project semantics.
